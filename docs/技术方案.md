# 尼康 Z50 II 照片传输 App 技术方案

> 项目代号：NikonSync（尼康速传）· 仅 Android · Flutter + Kotlin
> 日期：2026-09-13 · 状态：待确认

---

## 1. 目标与范围

把手机连上尼康 Z50 II 的 Wi-Fi，浏览相机存储卡中已拍摄的照片/视频，手动选图下载或全量一键下载到手机本地相册，并支持边拍边自动同步新照片。

**本期范围内**：Wi-Fi 无线连接、照片/视频浏览、手动多选下载、全量下载、自动同步新照片、下载去重。
**本期不做**：iOS/Web、USB 连接（作为后续兜底方案）、遥控拍摄、删除相机文件、RAW 转 JPEG。

## 2. 可行性结论（已核实的依据）

| 事实 | 来源 |
|---|---|
| Z50 II 官方支持"连接至智能设备"（Wi-Fi 热点/共享网络两种模式）和"连接至电脑"（配对 Wireless Transmitter Utility），相机端均有 Wi-Fi 接入点模式，屏幕显示 SSID/密码 | 尼康官方在线手册、WTU 帮助页 |
| 尼康相机 Wi-Fi 直连模式下，相机会在 **TCP 15740 端口**提供标准 **PTP/IP** 服务；客户端无需官方配对，只要在握手时使用尼康官方 App 同款固定 GUID + 友好名称，相机即视为已配对设备，直接放行完整操作集 | 开源项目 aero-shutter（Go 终端 + Capacitor 移动端，已支持 D 系列 9 款 + Z50/Z6/Z7） |
| PTP/IP 双通道握手、GetStorageIDs/GetObjectHandles/GetObjectInfo/GetThumb/GetPartialObject 分块下载、ObjectAdded 事件监听（边拍边传）均已被开源实现验证 | aero-shutter、mmattes/ptpip、malc0mn/ptp-ip |
| 未经认证的客户端虽能完成 TCP/PTP 握手，但只能拿到受限操作集（gphoto2 在 Z8 上实测被拒绝大部分操作）——印证了"必须用官方 App GUID 仿冒"这一路径 | gphoto/libgphoto2 #1135 |

**唯一的硬风险**：aero-shutter 的机型清单里有 Z50（一代）但没有 Z50 II。Z50 II 是否沿用同样的 GUID 放行机制，**必须在 M0 用真机验证**，这是整个方案的 Go/No-Go 决策点。验证不通过的备选路径见第 8 节风险表。

## 3. 总体架构

```
┌────────────────────────────────────────────────┐
│ Flutter UI 层 (lib/)                            │
│  连接页 · 相机相册 · 下载管理 · 自动同步 · 设置   │
│  Riverpod 状态 · go_router 路由 · drift 下载记录  │
└──────────────┬─────────────────────────────────┘
               │ MethodChannel(指令) + EventChannel(事件流)
┌──────────────┴─────────────────────────────────┐
│ Kotlin 原生层 (android/app/src/main/kotlin/)    │
│ ┌────────────────────────────────────────────┐ │
│ │ PtpIpClient —— 纯 Kotlin 实现的 PTP/IP 客户端 │ │
│ │  · 双 TCP 通道（命令 + 事件），端口 15740     │ │
│ │  · 握手：InitCommand(GUID) → InitEvent      │ │
│ │  · OpenSession / 枚举 / 取缩略图 / 分块下载   │ │
│ │  · 事件监听：ObjectAdded / 断线检测          │ │
│ └────────────────────────────────────────────┘ │
│ CameraNetworkScanner —— 网段扫描定位相机 IP      │
│ WifiGate —— 引导连热点、socket 绑定 Wi-Fi 网络   │
│ MediaStoreSaver —— 保存到系统相册                │
│ DownloadQueue —— 串行下载队列 + 进度上报         │
│ SyncService —— 自动同步前台服务                  │
└────────────────────────────────────────────────┘
```

**职责边界**：Kotlin 层负责一切与相机和网络相关的工作（协议、下载、保存文件），对 Flutter 只暴露少量方法与事件；下载记录、去重判断、UI 状态全部留在 Flutter 侧（drift 数据库），保证单一事实来源。

### 通道接口（初版定义）

```kotlin
// MethodChannel: "nikonsync/ptp"
scanForCamera()            → List<CameraInfo>   // 扫描当前网段 15740 端口
connect(ip)                → CameraInfo         // 握手 + OpenSession + 电池/型号
disconnect()
listObjects(storageId, filters) → [ObjectInfo]  // handle/文件名/大小/时间/格式
getThumbnail(handle)       → Uint8List          // GetThumb
download(handle, fileName) → taskId             // 入队，异步执行
cancel(taskId) / cancelAll()
getBattery()               → Int

// EventChannel: "nikonsync/events"
// onProgress(taskId, bytes, total) | onTaskDone(taskId, savedUri)
// onObjectAdded(handle) | onDisconnected(reason) | onLog(msg)
```

## 4. 核心技术设计

### 4.1 连接与引导（Wi-Fi）

1. 相机端操作（首次，App 内图文引导）：`MENU → 连接至智能设备 → Wi-Fi 连接`，相机开热点并显示 SSID/密码。
2. 手机侧：App 拉起系统 **Wi-Fi 设置面板**（`Settings.Panel.ACTION_WIFI`，Android 10+ 无法静默连网，这是合规做法），用户点一下相机热点即返回。
3. 成功连过一次后，用 **WifiNetworkSuggestion** 向系统登记该热点，之后相机开机时系统大概率自动回连，实现"打开 App 即连上"。
4. 相机热点没有互联网。App 用 **ConnectivityManager.bindProcessToNetwork / Network.bindSocket** 把相机 socket 绑定到 Wi-Fi 网络，**蜂窝数据照常可用**（aero-shutter 同款做法），不会出现"连相机就断网"的体验问题。
5. 定位相机 IP：优先读 Wi-Fi 网关 + 厂商常见地址（192.168.1.1 等）直接探测，失败再并发扫描 /24 网段的 15740 端口。

### 4.2 PTP/IP 协议层（Kotlin 自研，核心工作量）

- 报文格式：4 字节小端长度 + 4 字节小端类型，标准 PTP/IP 封装。
- 握手：命令连接发 `InitCommandRequest`（官方 App 的固定 16 字节 GUID + 友好名）→ 收 `InitCommandAck` 拿连接号 → 用连接号建立第二条事件连接 `InitEventRequest`（必须先于 OpenSession）。
- 会话与枚举：`OpenSession → GetStorageIDs → GetObjectHandles`（按格式过滤：JPEG 0x3801、NEF 0x3000/0x3800、MOV/MP4 0x300D）→ `GetObjectInfo` 取文件名/大小/时间。
- 缩略图：`GetThumb`；尼康厂商扩展大图（aero-shutter 验证过的 GetLargeThumb）作为可选增强。命令通道同一时刻只能跑一个事务，缩略图走串行队列 + Flutter 侧 LRU 文件缓存。
- 下载：`GetPartialObject` 分块拉取（参考实现用 4MiB 块，真机实测确定最优块大小），流式写入、恒定内存，支持取消与断点重试；小文件直接 `GetObject`。
- 事件：事件连接上监听 `ObjectAdded`（新照片）与断线，喂给自动同步。
- 保活：周期性轻量 PTP 操作（如查询电量）防止相机 Wi-Fi 休眠断链；断线用指数退避自动重连并透明重开会话。

### 4.3 下载与本地存储

- 保存到系统相册：**MediaStore**，图片入 `Pictures/NikonSync/`，视频入 `Movies/NikonSync/`（API 29+ 无需存储权限，同时相册 App 立即可见）。
- minSdk 定为 **29**（Android 10），省掉旧版分区存储兼容层，2026 年覆盖面足够。
- NEF 原样保存，不做转码；视频同样原样下载。

### 4.4 自动同步（边拍边传）

- 前台服务（`dataSync` 类型）+ 常驻通知，持有 PTP 事件连接。
- 收到 `ObjectAdded` → 自动 `GetObjectInfo` → 按用户规则过滤（原图/仅 JPEG/是否含视频）→ 入下载队列 → 通知栏显示进度。
- 注意：SnapBridge 的"自动发送"只传 2MP 小图；本 App 的自动同步下载的是**存储卡原图**（全尺寸 JPEG/NEF），这是与官方体验的差异点，也是卖点。

### 4.5 去重与下载记录

- Flutter 侧 drift 数据库记录：相机 GUID + 文件名 + 文件大小 + 修改时间 + 保存路径。
- 相册列表扫描时对照记录：已下载的文件打"已下载"角标；"全量下载"只传未下载过的（增量）。

## 5. UI / 页面设计

| 页面 | 内容 |
|---|---|
| **连接页**（首页） | 连接状态卡片（型号/电量/照片数）、"连接相机"按钮 + 分步引导（开相机 Wi-Fi → 连热点 → 自动发现）、已保存相机记忆 |
| **相机相册** | 缩略图网格（按拍摄日期分组）、格式筛选 chips（JPEG/RAW/视频）、多选模式（全选/反选）、已下载角标、底部操作栏（下载所选 / 全量增量下载） |
| **下载管理** | 进行中/已完成/失败三类任务、单项与整体进度、失败重试、取消 |
| **自动同步** | 总开关、过滤规则（原图格式/是否含视频）、运行状态与传输日志入口 |
| **设置** | 保存目录说明、已下载记录清理、协议调试日志（排查问题用）、关于 |

设计语言跟随系统 Material 3，深色模式自动适配。

## 6. 权限清单

| 权限 | 用途 | 备注 |
|---|---|---|
| ACCESS_WIFI_STATE / ACCESS_NETWORK_STATE | 判断 Wi-Fi 连接与网段 | 普通权限 |
| NEARBY_WIFI_DEVICES（API 33+，neverForLocation） | 网络建议/扫描 | 声明 neverForLocation 后不需要定位权限 |
| ACCESS_FINE_LOCATION（API 29–32） | 旧系统扫描 Wi-Fi | 运行时申请，仅 10~12 系统需要 |
| POST_NOTIFICATIONS（API 33+） | 自动同步前台服务通知 | 运行时申请 |
| FOREGROUND_SERVICE / FOREGROUND_SERVICE_DATA_SYNC | 自动同步服务 | 普通声明 |
| MediaStore 写入 | 保存照片视频 | API 29+ 无需权限 |

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| Z50 II 对仿冒 GUID 的放行行为与 Z50 一代不同 | **高** | M0 第一时间真机验证；备选 A：走"连接至电脑"模式并实现 WTU 等价配对握手（参考 libgphoto2 源码）；备选 B：抓包分析 SnapBridge 的 Wi-Fi 传输协议 |
| 上述全部不通过 | 中 | 兜底方案：USB OTG + PTP/USB（协议事务层代码完全复用，仅换传输层），体验稍差但 100% 可行 |
| Android 10+ 不能静默连热点 | 中 | Settings Panel 一步引导 + 网络建议实现"二次起免操作" |
| 相机 Wi-Fi 休眠导致断连 | 中 | PTP 保活轮询 + 指数退避重连 + 引导用户关闭相机省电选项 |
| 大文件（NEF ~30MB、视频 GB 级）传输中断 | 中 | 分块下载 + 断点续传 + 块级重试，UI 提供失败重试 |
| 相机热点下手机蜂窝被系统挂起 | 低 | bindProcessToNetwork 绑定相机 socket，蜂窝正常 |

## 9. 需要你准备/确认的

1. **确认本方案**（或指出要调整的点）。
2. 开发期间可用的 **Z50 II 真机 + Android 测试手机**（Android 10+，最好 13+），能安装 debug APK。
3. 提供相机操作截图或允许我按官方手册流程编写图文引导（连接至智能设备的菜单路径）。
4. App 名称偏好（暂定"尼康速传 NikonSync"，可改）。
5. 确认保存目录为系统相册的 `Pictures/NikonSync/`（否的话改为仅应用私有目录）。

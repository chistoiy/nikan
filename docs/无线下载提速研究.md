# 无线下载提速研究（2026-09-16）

> 问题：**Wi-Fi 下载照片还有没有提速的可能？**
> 方法：先定位物理层上限（否则协议层怎么调都是白费），再逐项排除 App 侧因素，最后给出可实测的路径。
> 结论先说：**AP 模式下已基本到顶，App 侧没有可挖的空间；有量级意义的只有"换频段（5GHz/STA 模式）"和"换传输方式（USB）"。**

## 一、结论摘要

| 路径 | 潜力 | 依据 |
|---|---|---|
| 继续优化 PTP/IP 协议层 | **≈0** | socket 层与分块策略都已到位（见 §三），且分块往返开销相对传输时间可忽略 |
| 关掉蓝牙、靠近相机（2.4GHz 共存/干扰） | **+20~50%？** | 2.4GHz 与蓝牙共用频段；这是零成本实验，值得一测 |
| **相机 STA 模式 + 5GHz 路由器** | **可能数倍** | Z50II 官方规格含 **802.11a/ac**、5180–5825MHz、5GHz EIRP 9.5dBm（2.4GHz 仅 3.8dBm）；但见 §四的注意项 |
| 改用 USB 数据线 | **11 倍（已实现）** | 实测 27.1 MB/s |
| 用 App 的 8M / 2M 画质档（不榨原图时） | **数倍（已实现）** | 传输量本身变小，是最"土"也最有效的提速 |

## 二、当前上限在哪：54 Mbps 就是 802.11g 的满速

真机日志长期稳定出现：

```
链路信号：3/4 格（-56 dBm）· 速率 54 Mbps          （旧日志，未带频段）
```

**为什么这个数字是关键证据**：802.11n 在 20MHz 带宽下的速率集合是
6.5 / 13 / 19.5 / … / 65 / 72.2 Mbps —— **里面没有 54**。54 Mbps 只出现在 **802.11g**。
也就是说，相机自建热点的空口是按 **11g** 协商的（虽然射频本身支持 n/ac）。

由此推算：

```
11g 54Mbps = 6.75 MB/s 理论 PHY
  减去 802.11 前导/ACK/退避/重传等开销 → 实际 TCP 吞吐约 20~25 Mbps
                                        ≈ 2.5 ~ 3.1 MB/s  ← 现实上限
实测：2.4 MB/s（最好一次）/ 1.5 MB/s（波动时）
→ 相当于实际上限的 50% ~ 95%
```

**这就是"提速空间"的全部家当**：在 11g 下最多再挤到约 3MB/s，而且靠的是少干扰、离得近，
不是靠改代码。

> 配套改动：链路日志现在会带上频段（`… · 速率 54 Mbps · 2.4GHz`），
> 一眼就能判断当前是不是 11g 场景。

## 三、App 侧已排除的因素（都查过，别再试）

| 项 | 现状 | 结论 |
|---|---|---|
| socket 接收缓冲 | 4 MB | ✅ 且**在 connect 之前**设置（窗口缩放才生效） |
| socket 发送缓冲 | 1 MB | ✅ 足够（命令包只有几十字节） |
| `TCP_NODELAY` | 已开 | ✅ 小命令不会被 Nagle 攒住 |
| `SO_KEEPALIVE` | 已开 | ✅ |
| Wi-Fi 省电流 | `WifiLock` = `WIFI_MODE_FULL_LOW_LATENCY` | ✅ 系统允许的最激进档 |
| 分块大小 | 4 MB（`PARTIAL_CHUNK_BYTES`） | ✅ 4MB/2.7s，往返开销占比个位数百分比 |
| 并行/流水线请求 | — | ❌ **协议不允许**：PTP/IP 只有一条命令通道，且相机同时只接受一个会话（上一个会话的释放窗口实测可达 3 分钟） |
| 0x94xx 厂商"高速通道" | 探针始终未通过 | ❌ 那些码是 **SDRAM 语义**（取景缓冲），不是卡内文件；且启用门槛是"输出与 0x101B 逐字节一致"以防下坏文件 |
| 手机端写盘拖累 | 数据经 MediaStore/FUSE 落盘 | ✅ 2.4 MB/s 远低于 FUSE 的能力，不是瓶颈 |
| 进度事件/主线程 | 300ms 节流、只走事件通道 | ✅ |

**一句话**：在这一层已经没什么可调的了。

## 四、唯一有量级意义的杠杆：让相机走 5GHz（STA 模式）

Z50II 的官方规格（尼康官网/各地官网一致）：

```
Wi-Fi 标准：IEEE 802.11b/g/n/a/ac        ← a 与 ac 只存在于 5GHz
频率范围：  2412–2462 MHz 以及 5180–5825 MHz
最大 EIRP： 2.4GHz 3.8 dBm；5GHz 9.5 dBm   ← 5GHz 发射功率是 2.4GHz 的约 2.5 倍
```

**但相机自己当热点（AP 模式）实测只跑 11g。** 要用上 5GHz，得让相机**加入用户已有的路由器**——
尼康官方文档里相机网络菜单有这一项：

```
MENU → 网络菜单 → 连接至智能设备 → Wi-Fi连接
   ├ AP mode   ← 相机当热点（我们现在用的）
   └ STA mode  ← 相机加入已有网络（本方案）
```

### 操作步骤

1. 相机：网络菜单 → 连接至智能设备 → **`Wi-Fi连接`** → 选 **STA mode** → 「创建配置文件」
   → 选中家里路由器的 **5GHz SSID** → 输入密码 → IP 配置选「自动」；
2. 手机：连**同一个路由器的 5GHz SSID**（注意别连到 2.4GHz 那个，否则还是 11g）；
3. 回 App：点「连接相机」。`connectSmart()` 会依次试已知地址 → 网关 → `192.168.1.1`，
   失败后**自动扫描手机所在网段的 254 个地址**去发现相机的 `15740` 端口，
   所以**不需要手填相机 IP**；
4. 调试面板 →「**无线测速**」→ 看频段是否变成 5GHz、吞吐是多少。

### ⚠️ 两个常见坑

- **路由器开了"客户端隔离 / AP 隔离"**：手机与相机即使在同一网段也互相不可见。
  现象是「未发现相机」。把该选项关掉即可。
- **手机连的是路由器的 2.4GHz SSID**：频段仍是 2.4GHz，白折腾。

## 五、立刻可做的实测流程（约 30 分钟）

| 步骤 | 操作 | 记录 |
|---|---|---|
| 1 | 相机 AP 模式（现状）→ 调试面板「无线测速」选一张 ~20MB 照片 | 频段 / 协商速率 / 吞吐 |
| 2 | **关掉手机蓝牙**，重跑 | 对比差异 → 判断蓝牙共存的影响 |
| 3 | 相机切 **STA 模式接 5GHz**，手机连同一 5GHz，重跑 | 对比差异 → 判断频段的影响 |
| 4 | （可选）USB 下同样跑一次 | 作为上限参照 |

**「无线测速」探针是本次新增的仪器**：它把选中的文件真传一遍但**丢弃数据**（不落盘、不写下载记录），
报告平均吞吐、最慢区间、当前频段与协商速率，并**直接判读"还有没有空间"**——
不需要自己算。它的输出形如：

```
链路：2.4GHz · 协商速率 54Mbps · 信号 -56dBm
对象：DSC_5586.JPG（8.4MB）· 传输模式 HISPEED
结果：8.4MB / 4.1s = 2.05 MB/s（16.4 Mbps）
最慢区间：380ms（自 5.2MB 处起）——远大于平均值说明有停顿，不是稳定限速
判读：802.11g 链路（54Mbps），TCP 上限约 3MB/s，当前已基本到顶。要更快只能换传输路径：
      相机 STA 模式接 5GHz 路由器，或改用数据线（约 27MB/s）。
```

## 六、顺带说明：已经存在的"提速"手段

- **8M / 2M 画质档**：如果不需要像素级细节（发朋友圈、快速挑选），传输量本身就小几倍，
  这比任何协议优化都有效。大图页的「显示原图」只在真需要时才拉原图。
- **查看器开「显示原图时保存到手机」**：一次传输同时完成"看"与"存"，
  不会出现"先看一遍、再下载一遍"的双份流量；已下载过的图片直接从本地读。
- 仍存在的一处重复传输：先看原图（只进内存、不落盘）→ 再回相册点下载，会重传一遍。
  要消掉需要给原生加一个"把内存字节落盘"的入口，收益取决于使用习惯，**暂不做**。

## 七、最终判断

1. **无线（AP 模式）在 11g 下已接近上限**，不要再指望 App 侧挤出明显速度。
2. 有量级意义的只有两条：**5GHz（需相机 STA 模式）** 与 **USB（已实现，27.1 MB/s）**。
3. 因此建议的下一步不是继续调协议，而是：
   - 把 **STA 模式 + 5GHz** 写进连接向导，作为"想要更快时的进阶选项"；
   - 在链路面板上**显示当前频段**（已加到日志，UI 可后续跟进）；
   - 用实测数字决定值不值得为 STA 模式做专门的发现/引导 UI。

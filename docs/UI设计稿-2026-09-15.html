尼康速传 · 界面设计稿

按现有页面与操作逻辑重画一遍，并补齐白天/深色两套主题。设计目标只有三句话： 任何耗时操作都要能看见进度、任何失败都要给出下一步、单手可达的主操作放在下方。 本稿所有状态都对应真机实测过的行为（Z50 II · 固件 1.02 · Wi-Fi 智能设备模式）。

① 进度可见性

传输超过一秒就必须有真实百分比 + 已接收量 + 速率 + 已用时； 连续 8 秒没有新数据就转"可能卡住"的警示态。 只有转圈指示时，"正在传 20MB"和"已经卡死"在屏幕上长得一模一样。

② 失败可行动

报错必须包含原因与下一步：取景没画面要指出"相机是否在回放/菜单/休眠"； 对焦被拒要说明档位与 AF 模式的影响；参数不可写要说清是哪一档限制。

③ 单手可达

主操作（下载、快门、浏览照片）固定在下缘 1/3 区域；顶部只放状态与低频入口。 所有可点元素 ≥ 40×40，间距 ≥ 8。

状态一览与关键流程

每个页面在"加载 / 空 / 失败 / 离线"四种情形下的表现要统一，禁止用无限转圈代替状态。

四态约定

状态表现禁止
加载有总量时给确定进度条，无总量时才用不确定动画无说明的转圈
空灰图标 + 一句原因 + 一个动作按钮空白页
失败原因（含相机响应码）+ 下一步建议 + 重试入口只写"失败"
离线占位图 + "返回重连"；自动重连时显示第 N/M 次静默变灰

连接与取景流程

① 连接直接对网关握手 → 失败且原因是 RST 时跳过网段扫描，提示"相机在释放上一个会话"
② 自动重连2/4/8/15/20/30×4 秒（约 2.8 分钟覆盖相机释放窗口），保留相机 IP
③ 进取景0x9201 3s → 8s 两段超时；失败不吞，直接报原因
④ 取帧自调度循环 + ≥20ms 间隔；失败区分 NotLiveView 与其他
⑤ 中断恢复0x9202→0x9201 强制重进，3 秒节流，3 轮失败转手动
⑥ 退出0x9202；无论是否应答都按已关闭处理，避免标志位卡死
